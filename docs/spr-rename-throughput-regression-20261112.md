# MOV / zero-idiom：吞吐与其他负载退化核对

吞吐使用完整原 manifest、原预热、原线程计划；固定 CPU 24–35，输入身份哈希扫描关闭，M1/OFF/ON 串行交错，各版本轮换先后位置。用户要求停止后，剩余测量、native 审计及后续自动任务均已终止。本报告仅采用 Zstd 已完成的两组配对；第三组的单独 ON 输出未纳入吞吐比较。XZ 尚未开始本轮串行吞吐测量。这是完整输入的少次重复诊断，未达到项目要求的 30 组稳定吞吐验收。

|---|---:|---:|---:|---:|---:|
| Zstd | -7.12% | -6.26% | +0.93% | -7.93% | -7.01% |

百分比由每组耗时比的中位数计算：`(1/ratio - 1) × 100%`，以相同功能人口为分子。进程墙钟包含读入和启动，simulator 墙钟单独列出。吞吐 manifest 的全部源路径和完整边界与原 manifest 一致；逐次输出的逐核人口和完整时间计分结果与既有同版本精度回放一致。吞吐运行关闭输入哈希扫描，因此不声称逐次重新取得内容哈希。其余四个负载尚无本轮串行吞吐测量。

绝对误差单位为 cycles/retired macro。五负载等权 CPI MAE：0.191599 → 0.179390；MAPE：12.99% → 10.89%。

CPI 使用维护的时间比较函数及已审计参考，核对当前 oracle 哈希、候选/冻结版功能身份和逐核计分人口。该独立 CPI-only 比较不宣称 fresh native 审核完成，也不升级主退休缓存 PMU 或硬件等价认证。

精度只有 XZ 小幅退化；Zstd/FLAC/Graph500/Marian 的 CPI 绝对误差均缩小。预测 CPI 升高本身不等于精度退化，Zstd 和 Graph500 原本低估。
