# v2 后续优化：响应关键 bank 门控与预热消融（2026-09-16）

## 结论与交付状态

沿 v2 的“有来源证明、局部 max-plus 修正、逐步收窄作用域”思路，测试了
bank/PRE-only 和响应关键 bank 门控两个候选。后者使严格 33 配置的 CPI MAE
从 **0.054931 降到 0.054126**，MAPE 从 **5.0614% 降到 4.9821%**；
但 LBM 全量、逐核及既有正负窗口均有回退，**不替换维护 v2 默认，也不合入生产代码**。
不能把这次总体改善称作“保留 LBM 收益的稳定 v3”。

维护 `configs/gem5-fs-native-kernel.cfg` 仍默认开启 v2；
`--store-wait-relief false` 后重跑仍是原始回退。新开关只存在于
`tmp/store-wait-v3-20260916/worktree/` 隔离副本，通过配置文件使用。
没有调 DRAM 标量、放宽原有兼容性 guard、使用负载/PC/核心数补偿或重新启用 ACT 扩展。
没有 commit 或 push。

## 两个候选的区别

v2 先要求移除合格同核前序 store 预约后，本 bank 的 command 时间提前，再按
bank/PRE、bank-group、channel/rank 和数据总线一起移除的联合响应差值发放
credit。bank command 提前不等于它独立影响最终 response；共享约束可能仍盖住它。

1. **bank-only**：反事实只移除合格 bank/PRE floor，共享 group/channel/rank/bus
   floor 不变，credit 使用这个更窄反事实的 response 差值。
2. **critical**：先要求上述 bank-only 反事实能够严格提前最终 response；通过后，
   使用原 v2 的联合反事实 credit。它是覆盖范围更小的实验门控，不是已证明必要的
   DRAM 语义修复；同核前驱覆盖的联合等待即使不满足新门控，也未必应被保留。

两者均保留 ACT/window、源 owner 校验、实际 TSO send 位移上限、固有服务下界、
片段组 max 以及 FRFCFS 替换失效证书的规则。canonical 日历不在局部反事实中改写，
但核心反馈仍会改变后续 epoch 的到达、调度和缓存状态。

## Graph500 C32：预热影响已用消融定位

gem5 CPI 为 2.386466。此前“测量零 credit、预热已分叉”的观察，现在得到更强证据：

| 模式 | warmup relief 组 / 服务周期 | warmup barrier | 测量 relief 组 / 服务周期 | FastSim CPI | 相对误差 | 绝对 CPI 误差 |
|---|---:|---:|---:|---:|---:|---:|
| off | 0 / 0 | 5258793 | 0 / 0 | 2.325654 | −2.5482% | 0.060812 |
| v2 | 13 / 615 | 5265655 | 0 / 0 | 2.287749 | −4.1365% | 0.098717 |
| warmup-only | 13 / 615 | 5265655 | 0 / 0 | 2.287749 | −4.1365% | 0.098717 |
| measurement-only | 0 / 0 | 5258793 | 1 / 76 | 2.325654 | −2.5482% | 0.060812 |
| bank-only | 0 / 0 | 5258793 | 1 / 76 | 2.325654 | −2.5482% | 0.060812 |
| critical | 0 / 0 | 5258793 | 1 / 76 | 2.325654 | −2.5482% | 0.060812 |

warmup-only 的逐线程周期与 cache/CHA 结果精确等于 v2；measurement-only
的逐线程周期与 cache/CHA 结果精确等于 off。后者虽消费 1 组 76 周期，但不改变
这些最终结果，进一步说明服务 credit 不是最终周期差的加性归因。

v2 的 13 组预热消费分布为 C4: 3/96、C10: 2/140、C13: 1/31、
C15: 3/99、C18: 3/117、C31: 1/32（组/服务周期）。
bank-only 和 critical 的预热消费均为零，表明在这次轨迹中收窄规则阻止了分叉。

**可确认的因果范围**：该回退由预热期间的修正及其传播状态足以复现，而非必须
依赖测量期的直接扣除。**尚未确认**：首个关键动态请求，以及 cache、DRAM、
dependency/response scoreboard、全局 barrier 各自的贡献。615 个服务周期不能解释为
测量周期差的线性来源，也不能据此证明预热状态保留本身有 bug。
