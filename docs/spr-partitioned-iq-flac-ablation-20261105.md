开启后总体等待累计增加 15,280，而事件数减少 1,720；仅看事件数会漏掉单次等待长度的变化。核心 0 的等待增加 20,907 且 active cycles 增加 41,538，方向支持该核存在更强 IQ 准入压力。开启时各核观测到的总 IQ 占用峰值低于共享上限 248，而关闭时达到 248；这与开启后某个分区先耗尽的模型机制一致。但输出没有 execution/memory/store-data 各分区的 occupancy、满队列事件或具体 UOP 证据，无法判断是哪个分区或哪条依赖导致，也不能从总峰值推断各分区的时间序列。

这些 stall 值是按 UOP 准入时间差累计，并非互斥的逐周期退休损失；不同 UOP 的等待可能在时间上重叠，同一条执行路径也会与 ROB、SQ 和其他资源延迟交织。两套配置下其他资源准入和后续反馈均会改变，因此不能把两次 IQ stall 累计的差额直接作为 CPI 差值的贡献，也不能把这些计数与其他 stall 计数相加。例证：IQ ON 的 ROB stall 累计为 425,664,837，远超四核 task active cycles 之和 10,031,415；两者人口口径也不完全相同。核心 2 的 IQ stall 反而减少 2,783，但 active cycles 增加 43,109，现有汇总无法证明其原因或将该核增量归因于其他任一机制。若后续要做归因，需要同一次受控回放的分区级、退休关键路径和重叠信息；当前未重新回放、未调参。
