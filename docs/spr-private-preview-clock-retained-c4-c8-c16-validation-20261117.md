## 吞吐口径

采用当前默认性能路径：`sim.cpi_attribution=false`、`core.response_materialized_uop_fast_kernel=true`、validated preload。C4/C8 Graph500 额外核对完整 `time_accounting` 与此前关闭快内核、开启归因的字段修复对照一致。

主指标为 `scope_metrics.throughput.user_uops_per_second / 1e6`，单位 M measured user UOP/s。模型同时处理原输入中的 kernel 工作，但吞吐分子与 CPI 的 user-plus-kernel 宏指令口径不同，不互换。输入身份、准备/验证、初始化、功能 warmup 和完整 process wall 各自报告，均不混入主测量分母。

按既定 high-frequency wrapper 使用 socket/NUMA1 的 CPU52–63 和既有 performance 策略，未更改 governor。C4/C8 同时运行时分别绑定52–55（4CPU）与56–63（8CPU）；C16单独绑定52–63（12CPU），因此16个目标核并不等于16个专属宿主核。启动频率快照保留，没有持续频率遥测。每例只有一次新测量，属于当前样本吞吐，不是吞吐接受门禁或可扩展性认证。

原 command.json 的 `host_cpu_budget` 曾记录 launcher 可用CPU总数，真正 worker 约束是 `actual_mask`；最终 `reporting-provenance.json` 明确记录两者并给出4/8/12的实际预算。PMU JSON中的 reference hash为原始审计文件哈希，最终 provenance 同时给出原路径/哈希及重序列化冻结副本路径/哈希，避免混淆。
