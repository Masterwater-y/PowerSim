# P0：C32 十负载回归与吞吐验证

规约变更说明（2026-09-11）：本次使用的是历史逐核 10M 截断数据，结论仅为等工作量
兼容性和开销诊断。按新的 [共同采集与计分终点规约 §3.0](project-goal-and-semantic-contract.md)，
所有核心在共同终点前的实际工作都必须计分；本文不能作为新口径的正式精度验证。

日期：2026-09-11。

## 对照范围

使用 `formal40-latest-complete-deps-20260910` 的 10 组 C32 FST、完整依赖附件、
冻结硬件配置及配对 gem5 参考。每核原计分目标为 10,000,000 用户 UOP，保留已有
native kernel 和功能预热。参考分母与 FastSim 分母分别沿用实际人口；不修饰已有微小差异。

修复前 binary 为 `f6ccc810e6dac73842264f687e00c5d479ef9411a6cf85505c96e58a7d8ae441`，
修复后为 `6d5b1a9775845f0768a1bb2b8489b6a83662a3bca35884ad76dfcc24aa6be14d`。
两者已冻结在本次产物目录，生产源码和 binary 未修改。

修复前使用原 manifest；修复后使用 `fastsim-binary-context-v1`，将执行记录数设为
原计分记录数。这样启用 P0 的计分提交与 PMU 拆分路径，同时保持完全相同的实际工作量。
这 10 组输入没有额外真实后缀，零后缀验证不能衡量补入额外竞争后的精度收益或额外工作成本。

## 测量方法

- 每个版本、每个负载各运行一次，共 20 次 FastSim；没有 gem5、重采或其他核数组。
- 两路并行，每个 NUMA 节点一条测量通道；分别固定物理 CPU 0–47、48–95 及对应内存节点。
  同一负载两版本紧邻执行，5 组先旧后新、5 组先新后旧。
- 运行前用 `mincore` 检查全部 FST 及附件，页面驻留率均为 100%，未触发额外预读。
  另保留逐进程的主要缺页、文件系统输入、CPU 时间与最大 RSS 观测。
- 主吞吐单位为 M user-UOP/s，分母为排除功能预热的测量墙钟，口径与此前 formal40 一致。
  CSV 同时保留全部实际 UOP 吞吐、用户宏指令 MIPS、预热后的墙钟及含预热的整个仿真墙钟。
- 聚合吞吐用总用户 UOP / 各 case 测量时间之和；另报告各 case 速率比的几何均值。
  这是配对的一次观测，不估计置信区间，也不把小幅变动断言为显著回退。

逐字段比较模型输出，仅排除主机墙钟、速率和 producer 条件变量等待次数。
单独验证新输出的 32 个 score marker 均关闭、退休终点与旧版本一致、
后缀人口和正式 PMU 均为零。计分外的执行状态无从省略：本次恰好没有额外记录。

## 结果

**10/10 配对通过，20 次运行全部成功。CPI、正式 PMU 和目标时序诊断逐字段不变。**

零后缀下全部 320 个计分终点均正确关闭；后缀人口及 PMU 为零。新版本同时与历史冻结模型结果一致。

随后逐一核对物理 FST 文件头的 `record_count`：320/320 份文件均满足
`warmup_records + executed_records == record_count`，没有未执行的尾部记录。
每个版本在十负载上共执行 6,553,320,034 条记录（含预热），每个负载计分约
3.2 亿用户 UOP。对话中的“每核 1000 条”仅为解释示例，不是实验截断参数。
原始核对记录为 `physical-fst-consumption-audit.json`。

吞吐聚合按总工作量 / 累计测量时间计算：**6.783 → 6.739 M user-UOP/s，变化 -0.641%**；
逐负载速率比几何均值变化 **-0.645%**，中位数 **-0.453%**，范围 **-3.102% 至 +0.141%**。
正式测量累计耗时 **471.786 → 474.829 秒**，变化 **+0.645%**；包括功能预热的整个仿真耗时合计变化 **+0.486%**。

最大观测降幅出现在 Neutron，约 3.10%；其余负载在 −1.18% 至 +0.14% 之间。这是一次配对观测，不能单独区分新增指令开销、编译布局差异与运行波动。
