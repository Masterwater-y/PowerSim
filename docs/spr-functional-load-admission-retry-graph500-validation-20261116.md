普通单片段 load 的预约冲突已消除，剩余冲突来自沿用旧安排的观察成员。减少冲突并没有补齐 CPI：目前不能将移位后的端口冲突或缺少一次失败发射占用认定为 Graph500 主要残差的已闭合解释。

P2 每个受支持 load 最多记录一次失败预约和一次 callback 唤醒，已接受 miss 不自动重试；这不是原生全部重发次数的逐次复现。共享 cache/DRAM 仍按既有一次提交顺序处理。共享迟到累计量含重叠事件，不能加成 CPI 贡献；读分支回退数也不代表全部特殊指令人口。

## 零额外 CPI 收益与宿主开销的原因

这里的“零”特指 P2 相对 P1 的最终时间核算相同；整套 P1/P2 相对 M4 的精度效果为恶化，不能写成整个候选完全没有改变时序。

现有 Sequencer 释放事件本来就在限制成功接收。P1 先等接收条件，再预约成功发射；P2 在这一等待窗口内增加一次失败预约，再跳到同一释放事件并预约成功发射。失败尝试的资源占用只有进一步推迟成功发射、依赖或退休，才会新增关键路径时间。本轮两例增加了失败预约数量，却没有改变最终 `time_accounting`。

原始计数还给出完全相抵的分账变化：

| 来源 | P1 FU 等待 | P1 接收等待 | P2 FU 等待 | P2 接收等待 | 两者累计和（P1=P2） |
| --- | --- | --- | --- | --- | --- |
| c04-854.graph500_s | 25,409,458 | 380,717,651 | 44,589,950 | 361,537,159 | 406,127,109 |
| c08-854.graph500_s | 49,309,803 | 741,856,941 | 86,971,405 | 704,195,339 | 791,166,744 |

C4 的 FU 等待增加 19,180,492 周期、接收等待减少同量；C8 对应为 37,661,602 周期。这个累计和仅核对等待类别的算术分账，不是非重叠关键路径周期，也没有用于计算 CPI。最终时间核算相同是独立检查；未逐 load 比较成功接受时间，不能推广为每条成员的时刻必然相同。代码入口见 [失败尝试／callback／成功预约](../src/simulator.cpp#L16748-L16790)。

宿主则确实付出了额外计算。P1 对普通非内存 UOP 也预约，并对处理的 UOP 推进日历水位；C4/C8 分别登记 40,001,651／79,972,435 次预约。P2 再增加 4,889,244／9,397,178 次失败预约。见 [每 UOP 水位与非内存预约](../src/simulator.cpp#L16249-L16261)。

每次 `reserve` 先搜索 `first_available`，随后 `observe` 内再次搜索并检查候选端口；维护 issue/load/store 的 `std::map`、端口／同类区间 vector 的插入／删除，窗口进入和提交还复制 live 日历。这些是代码可确认的计算工作，具体 CPU 占比尚无本候选的热点采样证明。见 [日历搜索与维护](../tmp/sparse-load-pressure-20261116/before/include/fastsim/functional_issue_calendar.hpp#L29-L139)、[窗口进入复制](../src/simulator.cpp#L20682-L20683)、[提交复制](../src/simulator.cpp#L21059-L21060)。区间跳转和固定 live 上限保证不依目标空闲周期扫描，不保证每个功能事件的常数开销足够小。

阶段测量定位了新增宿主时间：

| 来源 | OFF / P1 / P2 模拟秒 | P1 / P2 模拟耗时增幅 | P2−OFF 准备秒 | P2−OFF warmup秒 | P2−OFF 模拟秒 |
| --- | --- | --- | --- | --- | --- |
| c04-854.graph500_s | 15.043 / 20.161 / 20.713 | +34.023% / +37.696% | -0.103 | +0.722 | +5.670 |
| c08-854.graph500_s | 28.448 / 36.010 / 36.923 | +26.580% / +29.791% | +0.062 | +0.712 | +8.475 |

P1 已产生 P2 相对 OFF 新增 E2E 耗时的 89.548%（C4）／90.340%（C8）；这是本轮三组墙钟差值的比例，不是严格 CPU 因果归因。P2 相对 P1 再增加 E2E 0.657／0.893 秒。输入准备基本不变，纯模拟和功能 warmup 增加；前述辅助阶段没有被用于重构主分母。

因此这版候选为尚未取得关键路径收益的机制增加了覆盖全流的资源维护。下一步应先验证哪些失败预约确实改变最终成功发射／依赖／退休，再确定需要维护资源的范围；宿主优化需针对重复搜索、水位维护和 live 状态复制进行采样后取舍。当前保持关闭，不按重试次数直接追加经验 CPI，也不扩展其他负载。

## 守恒、身份与回退

两例 OFF／审计／P1／P2 共 8 个既有回放成功。宏指令、UOP、逐核 memory access、全量 memory access、Sequencer request、DTLB access 守恒；发射人口包含消除 UOP 修正和额外失败尝试。拒绝、重试、唤醒相等。OFF／审计的完整时间核算与冻结 M4 相同，审计的功能 PMU 计数与 OFF 相同。独立目标身份两例 valid。

标准构建、`fastsim_tests`、`fastsim_functional_load_admission_tests` 均 returncode 0；定向测试包括跨 chunk、复制隔离、独立空位、端口争用、十亿周期区间跳转、拆分回退、load→ALU 依赖和冷 miss 不重试。小容量场景拒绝／重试／唤醒各 115。见 [集成测试收据](../tmp/load-admission-retry-20261116/integration-check.json)。
