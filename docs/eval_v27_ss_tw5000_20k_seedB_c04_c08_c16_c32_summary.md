## 2. 指标口径

- `global pVr`: 全 workload 聚合后，用 `sum_cyc_pred` 对比 `ROI cycles` 的
  `cpi_uop` 误差。
- `workload pVr`: 单 workload 的 `pred_vs_roi_cpi_uop`。
- `win MAPE`: per-window `cpi_uop` MAPE，小分母窗口会显著放大该值。
  本文这批旧日志只输出了均值；评测代码后续会额外输出
  `win_mape_cpi_uop_p90` / `win_mape_cpi_uop_p99`，需要重跑后才能无损回填。
- `slowest top1/top2`: per-window 慢核预测命中率；总表中按 windows 加权。

## 4. 主要结论

1. c16 的 `global pVr=2.73%` 看起来最好，但这个聚合指标会掩盖严重 outlier。
   `W_chase_dram @ c16` 预测 `8.9427`、ROI `3.2879`，单 workload pVr 达
   `171.99%`。因此 c16 不能只按全局聚合误差判断为稳定。

2. c08 是本批里最均衡的一档。全局误差 `5.85%`，workload p90 `11.58%`，
   最大 outlier 是 `W_ads_ranking_proxy=26.07%`。这说明 v27 shared-state
   在 c08 上的部署侧泛化相对可用。

3. c04 的主要问题是高 CPI coherence workload 被低估。`W_false_sharing`
   pVr `25.97%`，同时它的 ROI CPI 高，直接把全局误差拉到 `13.65%`。

4. c32 仍是风险最大的一档。全局误差 `16.68%`，p90 workload pVr `41.55%`。
   主要问题集中在 `W_search_index_proxy`、`W_stream`、`W_chase_dram`、
   `W_graph_recall_proxy`。其中 `W_stream` 和 `W_chase_dram` 是高 CPI 低估，
   会直接影响 aggregate cycles。

5. 慢核定位随 core count 增加明显变差。weighted top1 从 c04 的 `32.12%`
   降到 c32 的 `11.27%`；top2 从 `58.03%` 降到 `18.92%`。这说明当前模型
   能学到一部分 aggregate CPI，但对 per-core rank/straggler 的形状还不稳。

## 7. 下一步建议

1. 把模型晋级门槛从单一 `global pVr` 改为组合门槛：`global pVr`、`p90 workload pVr`、
   `max workload pVr`、`slowest top1/top2` 同时过线。c16 本轮就是典型的全局指标
   被 outlier 抵消的例子。

2. 优先诊断 `W_chase_dram @ c16`。它是当前最异常的单点：aggregate CPI 被严重
   高估，但 median core MAPE 不高，说明少量窗口或少量 core 的 rollout 形状可能
   把周期累计推偏。

3. c32 应专项拆 `W_stream`、`W_chase_dram`、`W_search_index_proxy`、
   `W_graph_recall_proxy`。其中 stream/chase 是高 CPI 低估，会直接拖累全局 cycles；
   search 是低 CPI 高估，说明不同机制的偏差方向不一致。

4. 对慢核排序增加单独评估与训练约束。当前 c32 top1 只有 `11.27%`，说明即便
   workload aggregate CPI 可接受，也不足以支持 straggler-aware 的调度或诊断用途。
