# PaTGen 与 FastSim 的毕业论文研究主线及实验设计

日期：2026-10-14。

状态：选题与实验方案整理。本文汇总讨论形成的建议，供开题和后续研究使用；联合有效性、决策一致性与端到端加速均为待验证目标，不代表已经完成的实验结果。负载、参数取值和规模尚需根据采集可行性与参数覆盖情况确定。

## 1. 选题目标与核心问题

毕业论文计划包含两个主要贡献点：已发表的 PaTGen，以及正在研究的 FastSim。论文需要围绕一个共同问题组织两个工作，形成从方法到系统应用的完整证据链。

建议研究主线为：**面向云负载的、保持时序行为与优化决策一致性的高效微架构评估。**

共同研究问题是：

> 如何在降低评估成本的同时，让经过负载简化和模拟近似后的评估系统，仍然得出与真实负载一致的架构优化结论？

核心思路是对两个对象分别进行近似：PaTGen 简化复杂应用及其软件栈，FastSim 简化昂贵的微架构模拟过程。两者共同保留影响性能变化和优化决策的关键动态行为。

建议题目：**《面向云负载的时序行为保持与快速微架构评估方法研究》**。

可用于开题报告的中心论点：

> 本论文研究云负载性能评估中的两层近似：通过 PaTGen 保留负载的关键时序行为，通过 FastSim 高效重建这些行为在不同微架构上的性能表现，并以端到端优化决策一致性验证两层近似的联合有效性。

## 2. 两个贡献点如何形成系统关系

### 2.1 两个工作的定位

| 贡献 | 简化的对象 | 保留的关键内容 | 在系统中的作用 |
|---|---|---|---|
| PaTGen：时序行为保持的代理负载生成 | 复杂应用及其软件栈 | 阶段结构、指标波动、执行行为的组合关系 | 提供可执行、可复用的行为载体 |
| FastSim：面向参数探索的快速微架构模拟 | 昂贵的详细微架构执行过程 | 指令依赖、资源约束、访存竞争及其对性能的影响 | 提供可配置的性能重建机制 |

PaTGen 通过阶段划分、MEU 组合和阶段内时序优化提高代理负载的行为保真度，并已通过阶段分析和 DVFS governor 排序等下游任务研究时序相似性的价值。已有工作见 [PaTGen 论文](https://dl.acm.org/doi/full/10.1145/3816437)。

FastSim 的项目目标包括绝对 CPI/PMU 精度与微架构参数变化后的趋势、幅度和排序一致性，见 [项目目标与语义合同](project-goal-and-semantic-contract.md)。其论文贡献应具体说明哪些机制需要保留、如何紧凑建模，以及这种近似为何能够保留参数敏感性；实现速度本身不足以完成这一论证。

### 2.2 从时序相似走向架构响应一致

参考配置上匹配平均 CPI 或 MPKI，并不自动保证代理能正确预测扩大缓存、增加核心资源或改变内存配置后的收益。两个负载可能在参考配置上表现接近，但工作集、依赖关系或阶段交替方式不同，导致对架构变化的响应不同。

因此，两者结合后的核心目标是：

> 在参考配置上生成的代理，是否对未见架构配置作出与真实负载相似的响应？FastSim 是否能够保留这种响应，并据此选择有效的配置？

“架构响应一致性”是建议新增的联合研究目标，不能由 PaTGen 和 FastSim 的独立结果直接推出。

### 2.3 完整评估链与接口

```text
真实云负载
    │ 在参考配置上采集行为特征
    ▼
PaTGen：生成保留阶段与时序特征的可执行代理
    │ 采集功能指令、访存及必要的同步信息
    ▼
FastSim：在候选微架构配置下重建性能
    │
    ▼
配置排序、瓶颈分析与优化方案选择
    │
    ▼
在真实负载／gem5 上验证最终决策
```

PaTGen 的 CPI、MPKI 序列用于生成代理；FastSim 消费代理实际执行得到的功能信息，自行预测目标配置下的性能。参考配置的 CPI 曲线不能作为目标配置的时序答案直接回放。目标配置的 gem5 issue、complete、commit 时间或缓存路径标签也不能进入 FastSim 的正式预测输入。

论文需要证明联合链条的有效性，而不是仅展示代理可以输入模拟器。现阶段不需要为了形式上的“闭环”增加 FastSim 反馈生成代理的模块；如果后续研究此类反馈，应另设数据隔离和独立验证，防止代理针对模拟器误差进行补偿。

## 3. 研究问题与基础对照

建议围绕以下问题组织实验：

1. PaTGen 是否保留真实负载在未见配置上的性能响应？
2. FastSim 是否保留真实负载与代理负载的性能响应？
3. 两层近似组合后，能否选出对真实负载有效的架构配置？
4. 更好的时序保真度，是否带来更小的决策损失？
5. 将准备、采集与模拟全部计入后，完整系统是否降低评估成本？

对每个真实负载 W，生成代理 P，建立四组基础对照：

| 组别 | 负载或输入 | 评估方式 | 用途 |
|---|---|---|---|
| A | 真实负载 W | gem5 | 架构评估参考 |
| B | PaTGen 代理 P | gem5 | 测量代理替代误差 |
| C | 真实负载的功能 trace | FastSim | 测量模拟近似误差 |
| D | PaTGen 代理的功能 trace | FastSim | 最终系统 |

A—B 检查代理替代；A—C 和 B—D 检查模拟近似；A—D 检查最终系统。四组均需明确配置、测量范围和输入来源。

对同一可比标量指标，差值可分解为 D−A = (B−A) + (D−B)。保留带符号误差，检查代理误差与模拟误差是否相互抵消。A—D 接近而两个中间误差很大，不能证明两层近似各自可靠。此分解也不等于配置排序或决策损失可以线性分解。

gem5 是本项目的微架构精度参考，其结果不自动等于真实硬件绝对性能。若论文增加硬件验证，需另行证明目标身份、事件语义和测量范围的可比性。

## 4. 数据集、配置空间与冻结规则

### 4.1 工作负载选择

先从 PaTGen 原有负载中选择 6 个，依据实际采集特征覆盖不同动态行为：

| 类型 | 需要覆盖的行为 |
|---|---|
| 计算占主导 | 对核心执行资源敏感 |
| 缓存敏感 | 对容量和局部性敏感 |
| 内存访问占主导 | 对访存延迟和并行度敏感 |
| 明显阶段交替 | 计算与访存阶段转换 |
| 突发型 | 短时资源压力变化 |
| 多线程交互明显 | 竞争、同步和等待 |

类型可以重叠，具体负载名单待 profiling 和真实负载在 gem5 中的运行可行性确认后冻结。选择理由应来自行为特征，不应来自已有误差大小。使用替代内核只能支持该内核的结论，不能替代真实云负载的端到端证据。

### 4.2 代理与模型冻结

- 选定参考配置 θ₀，仅在该配置上采集用于生成代理的特征。
- 每种代理方法生成代理后，冻结代码、MEU 参数和执行控制方式。
- 同一代理在未见配置上复用，不为每个测试配置重新生成或重新拟合。
- FastSim 模型开发负载与最终测试负载分开；测试负载可以生成自己的代理，但不能再用于调整模拟器机制或常数。
- “未见负载”“未见配置”“未见核数”分别命名与统计，不能相互代替。
- 随机生成方法记录随机种子；完整评估应检查多个种子的波动，不能只保留最优种子。

### 4.3 参数扫描与决策空间

参数响应实验建议先选择私有 L2 容量和共享 LLC 容量，各取 3 档，组成 3×3=9 个配置。具体取值从实际 gem5 基线出发，确认合法几何、bank/slice 分配和运行时激活情况。ROB、内存参数可在后续扩展，不能仅因配置文件暴露了参数便认定已验证支持。

决策实验采用固定总缓存容量预算：

```text
核心数 × 每核私有 L2 容量 + 共享 LLC 总容量 = B
```

在满足预算的若干合法分配方案中选择配置。增加私有缓存会减少共享缓存，形成真实权衡。预算 B 的具体数值和分配方案待基线确认；它是容量预算，不能直接解释为芯片面积或硬件成本等价。

9 点响应扫描与固定预算的决策集合是两个实验空间；前者不一定含有足够多的等预算配置，需要分别设计和记录。

## 5. 五类实验

### 5.1 实验一：代理在未见配置上的有效性

目的：仅用 gem5 比较 A 与 B，排除 FastSim 误差，检验代理是否保留架构响应。

测量内容：

- 全局与阶段级 CPI，以及事件语义明确的缓存／分支指标。
- 相对于各自参考配置的性能变化。
- 变化方向、变化幅度和候选配置排序的一致性。
- 阶段级失真与全局误差抵消情况。

用 CPI 定义响应时：

```text
R_W(θ) = CPI_W(θ) / CPI_W(θ₀)
R_P(θ) = CPI_P(θ) / CPI_P(θ₀)
响应差 = |R_P(θ) − R_W(θ)|
```

该指标衡量 CPI 响应，不自动代表应用吞吐或任务完成时间。真实负载与代理的指令人口通常不同，比较时保留各自真实分母。

建议图表：真实负载与代理的配置响应曲线、响应差热力图，以及一个阶段级对照案例。

### 5.2 实验二：FastSim 的响应保持能力

目的：比较 A—C 与 B—D，检验模拟近似是否保留参数响应，并测量吞吐和内存开销。

需要严格区分两种输入模式：

| 输入模式 | 可以验证的能力 | 成本与边界 |
|---|---|---|
| 每个配置使用对应配置的功能 trace | 给定执行路径上的模拟精度 | 各目标配置的采集成本均需计入 |
| 固定参考配置的功能 trace，改变 FastSim 配置 | 固定功能输入适用范围内的参数预测 | 需审计路径、线程交错和同步的变化 |

设计空间探索重点验证第二种；第一种用于建立精度证据和诊断。两类结果不能混合后宣称“一次采集、多配置探索”。

gem5 对每个目标配置独立执行参考实验。目标配置的功能输出可用于检查固定 trace 的有效范围，但其时序答案不能成为 FastSim 的预测输入。对于功能路径、等待人口或调度变化超出支持范围的案例，应报告失败原因、覆盖率和所需重新采集成本，不能只从统计中删除。

固定 trace 不自动保证目标配置共同终点处的逐核指令人口一致。若现有 validator 的人口或范围门禁无法通过，应保留失败结果，另行定义和验证适当的实验协议；不能通过改写分母或放松门禁宣称正式精度。

建议图表：gem5 与 FastSim 的响应曲线、CPI 绝对误差分布、排序一致性、支持范围和吞吐结果。

### 5.3 实验三：端到端配置选择

目的：检验最终系统是否能作出对真实负载有效的决策，这是两个贡献共同服务于同一目标的主要证据。

任务：在固定总缓存容量预算下，选择私有 L2 与共享 LLC 的分配方案。

各评估方法独立选择配置，随后统一回到真实负载＋gem5 上评价选中配置。A 给出候选集合内的参考最优配置；B、C、D 分别作出自己的选择。

主要指标：

- Top-1 命中率：是否选中真实最优配置。
- Kendall’s τ 等排序相关指标；对近似持平的配置预先规定并列处理规则。
- 决策损失（Regret）：所选配置相对真实最优配置的性能损失。

对越小越好的目标 J：

```text
θ* = 真实负载在候选集合中 J 最小的配置
θ_hat = 评估方法选出的配置
Regret = [J_W(θ_hat) − J_W(θ*)] / J_W(θ*)
```

Regret 优先于单独的 Top-1：若最优与次优几乎持平，选错配置的实际损失可能很小。报告每个负载及汇总结果，保留最差案例与统计不确定性。

目标 J 必须预先选择。采用 CPI 时，仅声称 CPI 意义下的配置选择；采用任务完成时间时，需在每个负载内部固定输入和逻辑工作量。真实负载与代理的绝对执行时间不宜直接相比，可分别相对 θ₀ 归一化，再评估响应与排序。

### 5.4 实验四：时序保持的作用与消融

目的：检验 PaTGen 的时序贡献是否提升最终系统的决策质量。

| 代理方案 | 作用 |
|---|---|
| 完整 PaTGen | 主方法 |
| PaTGen 去掉 DTSO | 检查阶段内时序优化的作用 |
| PaTGen 去掉阶段划分 | 检查阶段结构的作用 |
| 全局相似性较强的既有方法，例如条件合适时使用 Linear 或 CloudMix | 检查仅匹配全局指标的充分性 |

先在 gem5 下比较各代理的响应与决策，再在 FastSim 下重复，检查这些差异能否被保留。重点分析在全局指标接近的代理之间，时序保真度与真实负载 Regret 的关系。

消融可能同时改变全局相似性，必须实际测量；全局差异明显时，不能将全部决策差异归因于时序。多负载上的相关关系作为支持证据，结合受控消融和机制案例解释，不能单独作为因果证明。

可补充阶段重排实验，但重排可能改变缓存状态、共享干扰和全局指标，不应假定它是只改变顺序的完全等价对照。

建议选择一个成功案例和一个失败案例，展示阶段曲线、缓存状态变化、配置收益和最终决策。静态参数实验能够研究历史状态的影响，但不足以替代对动态 governor 的直接验证。

### 5.5 实验五：完整评估成本与收益

目的：验证从准备到配置选择的实际成本，而不是只报告 FastSim 内核速度。

分别记录真实负载 profiling、代理生成、功能 trace 采集、格式转换、存储、单配置模拟及实际工作流中的最终确认成本。研究阶段为建立完整参考矩阵而运行的所有 gem5 实验成本单独列示，不能混入系统部署成本，也不能被隐去。

对于 K 个候选配置，可用以下形式记录累计成本：

```text
T_system(K) = T_profile + T_proxy + T_trace + T_convert
              + Σ T_FastSim(θ_k) + T_confirm
```

只有验证了 trace 可复用范围，才可以将采集视为一次性成本。若某些配置需要重新采集，则把追加成本显式计入。如果 trace 来自 gem5，采集时间不能省略。PaTGen 简化软件栈不自动意味着指令数或执行时间减少，两者加速比也不能预先相乘。

建议画候选配置数量与累计评估时间的曲线，比较四组方法并展示摊销条件，同时报告峰值内存和 trace 大小。计时固定宿主资源、构建方式与放置策略，重复运行，报告中位数与波动；宿主 trace 处理吞吐与目标机器 IPC 分别命名。

## 6. 评估口径与关键边界

### 6.1 工作量、时间与阶段控制

在实施前核查 PaTGen 的 duration 和 MEU 启动延迟的具体语义：

- 固定迭代数／逻辑工作量：可研究配置变化对完成时间的影响。
- 固定墙钟持续时间：完成的工作量可能随配置变化，不能直接当作固定任务完成时间。
- 外部请求到达／启动节奏：可以是合法输入条件，但必须与执行本身的耗时区分。

真实负载与代理的阶段对齐规则预先声明。功能进度或工作单元对齐适合比较行为；真实时间对齐适合研究动态控制。不能通过任意拉伸时间轴或过度 warping 消除对优化决策有意义的延迟差异。

### 6.2 CPI、PMU 与任务级时间

正式结果服从 [accuracy-reporting-contract.md](accuracy-reporting-contract.md) 和 [project-goal-and-semantic-contract.md](project-goal-and-semantic-contract.md)，特别是以下规则：

- CPI 使用匹配 scope 的 active cycles 与各自真实 macro-instruction 分母；active scope 未认证时，CPI 及误差不可用，elapsed 时间另报。
- 正式多核 CPI/PMU 使用 first-core-target-common-end-v1 共同终点，记录逐核实际人口、预热与 reset 边界。
- 固定工作量的任务完成时间实验与上述 CPI 采集协议分别定义，不把固定指令窗口时间当作完整任务完成时间。
- FastSim 正式计分读取 scope_metrics；user 与 user-plus-kernel 不混用。
- native-FS 缓存参考来自守恒的 Ruby/SLICC native summaries；禁止使用 taotrace-path-class-v3 缓存代理字段作为原生真值。
- 使用 tools/run_native_kernel_fastsim_validation.py 的维护流程；目标身份另用 tools/validate_fs_oracle_identity.py 验证。
- 验证器 passed 不等于精度达标、吞吐认证或严格硬件 PMU 认证。缓存映射的 proxy／diagnostic 身份继续保留。
- 配置、几何与时间参数对应实际目标 config.ini，记录近似映射；不按工作负载或测试答案调延迟常数。
- 来源缺失、人口不匹配或语义不可比的结果明确列出，不能改写数据使其通过。

CPI 明细表模板：

| 负载／配置／对照组 | gem5 CPI | FastSim CPI | CPI 绝对误差（cycles/macro） | CPI 相对误差 | scope／有效性 |
|---|---|---|---|---|---|
| 待实验填写 | — | — | — | — | — |

CPI 绝对误差为 abs(FastSim CPI − gem5 CPI)，与相对误差并列。汇总表同时报告 CPI MAE 和 MAPE。PMU 报告区分 MAPE 与 WAPE，遵循合同的零参考值处理，记录有效样本数与尾部结果。

### 6.3 DVFS 与功耗范围

建议以固定预算的微架构配置选择作为主实验，DVFS 作为后续扩展。扩展前需要验证动态调频的时间尺度、同步等待、调度输入和功耗模型。

截至本文整理所参考的 2026-10-13 [同步 consumer 结果](fastsim-functional-sync-consumer-results-20261013.md)，该模式拒绝 execution windows/DVFS，且 active CPI 尚未认证。外部接口存在不表示所有模式组合均可用，执行时需重新核对支持范围。

没有独立验证的功耗／能耗来源时，不给出 EDP 或节能结论。若开展 DVFS，直接测试 governor 排序和真实目标上的决策损失，不能以静态配置结果替代。

## 7. 分阶段实施与决策点

### 7.1 第一阶段：最小联合试验

使用 3 个行为不同的真实负载，1 个参考配置加 4 个未见测试配置，完成四组对照；另确定一组合法的等预算缓存分配方案，执行一次配置选择。

此阶段回答三个问题：代理冻结后能否保留响应；FastSim 能否保留方向和排序；固定功能输入的适用范围是否足以支撑任务。记录 PaTGen 的执行控制语义、采集成本和失败案例，不设置事后筛选的成功门槛。

### 7.2 第二阶段：扩展与消融

第一阶段得到足够证据后，扩展到 6 个负载、9 点响应扫描以及独立的等预算决策集合，加入代理消融、随机种子和时间重复。冻结最终测试集合和模型版本，报告逐负载结果、汇总、覆盖率及失败原因。

若代理响应已经失真，优先研究代理的工作集、依赖和阶段表达；若代理在 gem5 下有效但 FastSim 排序失真，优先研究模拟机制；若固定 trace 路径失效，先界定输入与调度能力。不能用另一层的误差去补偿，也不应在试验失败时直接扩大矩阵。

### 7.3 第三阶段：可选扩展

在前两阶段完成后，再选择一个扩展方向：更多参数、核数泛化、真实硬件子集验证，或满足支持条件的 DVFS。根据证据选一个有价值的扩展，不要求全部同时完成。

## 8. 论文组织与预期材料

建议章节结构：

1. 绪论：云负载评估成本、关键动态行为和决策一致性的研究问题。
2. 背景与统一框架：代理替代与模拟近似、指标语义和误差来源。
3. PaTGen：时序行为保持的代理生成方法及已有验证。
4. FastSim：紧凑微架构建模、功能输入协议和适用边界。
5. 联合评估：未见配置响应、四组对照、决策损失、消融及端到端成本。
6. 结论与局限：适用负载／配置范围、失败案例和未来方向。

建议准备以下材料：

| 材料 | 要回答的问题 |
|---|---|
| 系统流程图与贡献定位表 | 两个工作为何属于同一研究问题？ |
| 数据划分、配置和预算表 | 结论基于什么范围，是否存在测试泄漏？ |
| 真实／代理／FastSim 的响应曲线 | 两层近似是否保留参数响应？ |
| 四组精度与带符号误差表 | 误差来自哪里，是否相互抵消？ |
| 配置排序、Top-1 与 Regret 图 | 最终选择对真实负载是否有效？ |
| 时序消融与成功／失败案例 | 时序保持为何有用，哪里不成立？ |
| 累计时间、内存与存储图 | 完整探索成本是否降低？ |

论文最终需要形成的证据链是：**PaTGen 提供保留关键时序行为的代理，FastSim 保留可支持范围内的架构响应，两者组合在可控成本下作出对真实负载有效的配置选择。** 如果实验不支持其中某一环，应据此收窄结论或继续研究，不能把待验证目标写成既成贡献。
