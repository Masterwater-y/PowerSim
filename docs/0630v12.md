# 0630 v12 方案、实验结果与问题分析

日期：2026-06-30

## 当前 v12 方案

v12 的目标是提高跨核心数泛化、修复部署侧时间偏移，并为 PMU 预测保留更稳定的结构输入。

主要设计：

- UOP 输入压缩：每条 uop 从 6 个普通 token 压成 1 个 `<UOP>` position，字段由 `UopEncoder(op, rg, mk, rd, st, br)` 编码。
- 显式结构 token 保留：`<SYS>`、`<CFG_*>`、`<TRACE>`、`<C{i}_BEGIN>`、`<C{i}_END>`、`<TRACE_END>`、`<QUERY_C{i}>` 仍走普通 token embedding。
- 固定 summary pack：在 query 前加入 `<SUMMARY_PACK>` 和固定 32-core `<C{i}_SUM>` slot，使 query 附近的 global/core summary 相对位置在 c01/c04/c08/c16/c32 下稳定。
- attention features：保留 coherence/memory/global/core features，并加入时间相关 token feature：
  - global：`GF_TIME_START_SKEW`
  - core：`CF_TIME_START_REL`、`CF_TIME_LAG_TO_LEADER`、`CF_TIME_RANK`
- side tensor：保留 47 维 functional/PMU proxy/sharing/timing 特征，包含 `log1p_t_start_rel`、`log1p_t_start_skew`、`log1p_t_lag_to_leader`、`t_start_rank`。
- 删除旧 `tstart_proj`：时间不再通过单独 query projection 注入，而是进入 attention/side feature schema。
- PMU 输出头拆分：
  - `cpi_head`
  - `branch_head`
  - `cache_miss_head`
  - `dtlb_head`
- 训练和部署侧窗口：
  - 时间对齐仍保留。
  - `nmin=256` 是每核最小 uop 证据量，不是取消时间对齐。
  - 部署侧使用 soft-nmin tail-aligned planner，预算不足时降低有效 nmin，避免爆上下文。

## PMU 结果对比

PMU 主看 aggregate pred-vs-ROI 相对误差的 median。mean 会被低基数、稀疏事件拉爆，尤其是 `llc_miss`、`l2_*_miss` 等在部分 workload 中 label 很小。

| PMU key | v12 c08 median | v12 c16 median | v11 c08 median | v11 c16 median | v11 c32 median |
|---|---:|---:|---:|---:|---:|
| branch_miss | 15.97% | 11.94% | 13.66% | 17.41% | 30.37% |
| l1d_ld_miss | 32.56% | 30.95% | 16.58% | 17.48% | 29.41% |
| l1d_st_miss | 31.61% | 32.34% | 14.00% | 25.66% | 18.66% |
| l2_ld_miss | 37.11% | 58.08% | 30.70% | 19.14% | 61.49% |
| l2_st_miss | 84.80% | 48.68% | 51.33% | 48.38% | 49.12% |

| dtlb_miss | 13.67% | 17.85% | 12.82% | 16.77% | 16.87% |

结论：

- v12 PMU 没有整体优于 v11。
- `branch_miss` 在 c16 有改善，但 c08 略差。
- `dtlb_miss` 基本持平。
- L1/L2 miss 头在 v12 上变差，尤其 c08 的 `l1d_*` 和 c16 的 `l2_ld_miss`。
- PMU 标签聚合本身没有明显问题，CPI 的 window label 与 ROI label 基本一致。当前 PMU 问题更像 count 头尺度校准不足、稀疏事件相对误差不稳定，而不是部署切窗偏移。

## 为什么新改动没效果甚至变差

当前更可信的解释是多因素叠加：

1. **loss 与目标错位**  
   训练 loss 可以继续下降，但 high-CPI tail 仍系统性低估。当前 loss 没有足够惩罚高 CPI 下的相对低估。

2. **side feature 表达力不足**  
   最强 sharing 信号在 side tensor 里，但当前 side 注入基本是线性 projection 加到 query hidden。false sharing 需要的往往是交互项，例如：
   - `coherence_pressure_ncore × shared_store_rate`
   - `owner_switch_rate × active_cores`
   - `writer_coverage × store_density`
   - `t_start_skew × coh_pressure`

3. **summary pack 稳定位置，但不新增因果信息**  
   summary pack 主要解决 query 附近位置稳定，不会自动让模型学会 ownership bouncing。

4. **split PMU heads 对 CPI 不是直接收益**  
   split heads 能减少 PMU 任务互相干扰，但 CPI head 的核心输入和 loss 没有本质变化。

5. **4B 容量更大不等于泛化更好**  
   当前训练只有约 1.5 epoch，且每 workload/core 约 600 windows。4B 可能更容易拟合 seedA/val 分布的平均趋势，而不是学到跨 seed 的 causal rule。

6. **高 CPI tail 被压缩**  
   低 CPI workload 非常准，高 CPI/coherence/phase workload 系统性低估。这是典型 tail regression 问题。

## 是否应优先把 top sharing features 提升到 attention token

不建议作为第一优先级。

原因：

- top sharing features 已经和 CPI 强相关，说明信号存在。
- 直接提升到 attention token 需要改 schema、重建 windows/cache、重新训练。
- 如果根因是 loss tail 权重和 side branch 表达力不足，进 attention 也可能继续被平均化。

适合进 attention 的特征应该满足：

1. 它会改变 uop token 的解释方式。
2. 它需要被 transformer 在 trace token 间传播。

候选：

- `GF_COH_PRESSURE`
- `GF_COH_OWNER_SWITCH`
- `GF_COH_SHARED_WRITE`
- `GF_COH_FANOUT`
- `CF_COH_WRITER_ROLE`
- `CF_COH_SHARED_STORE_ROLE`

但当前已有一部分 coherence attention features。因此建议先做低风险实验，确认不是 loss/side branch 的问题。

## 预期解决方法

### E1：tail-aware CPI loss

先不改输入 schema，改 CPI loss。

目标：

- 修复 high-CPI tail 低估。
- 不让 compute/branch/int_div 等低 CPI 分布整体漂移。

建议 loss：

```text
L = L_base + lambda_tail * L_tail + lambda_under * L_under + lambda_anchor * L_anchor
```

其中：

```text
w_tail = 1 + alpha * sigmoid((log_cpi - q80) / tau)
```

- p0-p80 权重约 1。
- p90 权重约 2。
- p95/p99 权重约 3-4。
- 不按 workload 名硬编码，避免只记住 false_sharing。

CPI 误差建议同时约束：

```text
L_cpi =
    Huber(pred_cpi, label_cpi)
  + beta * Huber(log1p(pred_cpi), log1p(label_cpi))
  + gamma * Huber((pred_cpi - label_cpi) / (label_cpi + eps))
```

当前主要是低估 high CPI，因此加 asymmetric under-prediction penalty：

```text
under = relu(label_cpi - pred_cpi)
L_under = w_tail * Huber(under / (label_cpi + eps))
```

为防止低 CPI 漂移，加 anchor：

```text
L_anchor = 1[log_cpi < q70] * Huber(pred_new - pred_old.detach())
```

`pred_old` 可以来自当前 v12 ckpt 或 v11 teacher。

### E2：SideMLP / gated side branch

在不增加 attention 长度的前提下增强 side tensor 表达力。

当前近似：

```text
query_hidden = query_hidden + Linear(side_feats)
```

建议改为：

```text
side_delta = SideMLP(side_feats)
side_gate = sigmoid(Gate(side_feats))
query_hidden = query_hidden + side_gate * side_delta
```

收益预期：

- 学到 sharing/timing/mem density 的高阶组合。
- 不改 tokenizer schema。
- 不重建 windows/cache，最多重建 tensor cache 或直接用现有 side_feats 训练。
- 推理长度不变，速度影响远小于新增 attention token。

### E3：少量 sharing features 提升到 attention

只有在 E1/E2 仍不能修复时再做。

策略：

- 不把所有 top-correlated side features 全部塞入 attention。
- 只加入能改变 uop token 解释方式的少量 global/core sharing context。
- 保持 token 增量可控，避免 summary pack 后固定 overhead 继续扩大。

候选新增 attention token：

- global owner switch / writer coverage bucket
- global shared store intensity bucket
- per-core shared writer role bucket
- per-core hot-store-line participation bucket

### E4：teacher distillation

4B 不适合作为最终部署模型，但可以作为 teacher。

路线：

```text
v12 4B / tail-aware 4B -> teacher
v12 0.6B or 1.7B -> deployment student
```

目标：

- 保留 0.6B/1.7B 的推理吞吐。
- 用 teacher 输出或 calibrated target 改善 hard workloads。

### E5：实验判据

下一版不能只看 mean/median，需要固定 guardrail：

必须下降：

- `W_false_sharing`
- `W_ads_ranking_proxy`
- `W_phased_mix`

不能明显变差：

- `W_compute_int`
- `W_branch_storm`
- `W_int_div`
- `W_indirect`

建议阈值：

- hard workloads CPI error 下降至少 30% 相对比例。
- easy workloads CPI error 增幅不超过 1-2 个百分点。
- 全 workload mean/median 不恶化。
- PMU 作为次级指标，优先保证 CPI。

## 推荐下一步顺序

1. 先在现有 v12 schema 上实现 tail-aware CPI loss。
2. 使用当前 v12 4B ckpt 做 short finetune，不重建 windows。
3. 同时训练 v12 0.6B baseline，确认 schema 与模型尺寸的影响。
4. 如果 tail loss 改善有限，再加 SideMLP/gated side branch。
5. 如果 SideMLP 仍无法修复，再提升少量 sharing features 到 attention token，并重建 v13 数据。
6. 最后用效果最好的 4B/1.7B 作为 teacher 蒸馏 0.6B 部署模型。
