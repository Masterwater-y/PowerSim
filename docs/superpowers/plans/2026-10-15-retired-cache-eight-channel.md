# 退休 cache 指标与八通道重采集实施计划

用户已批准上一轮对话中的退休 load 方案，并要求直接实施、删除旧数据、使用八通道及缩短 warmup。
本计划由本会话直接执行；不改变历史请求事件的定义，不覆盖历史误差报告。

## 合同与范围

- 主指标新增独立命名空间 `retired_cache`：退休 load/store、L1/L2/L3 load miss、L1/FB/L2/L3 hit。
  绑定 SPR `MEM_INST_RETIRED` / `MEM_LOAD_RETIRED`，单位为架构退休宏指令。
- gem5 的服务事实来自独立 native lifecycle；在宏退休人口中归并。禁止 path_class 充当真值。
  同一宏多个成员的正资格按事件 OR；不完整、未解析、forwarding、远端/合并歧义保留逐事件 unknown。
- FastSim 仅记录最终接受的执行前缀，自行模拟服务；跨 chunk 保留宏成员，回滚不计数。
- 所有事件仍为近似预测，硬件等价未认证；错误路径对 cache 状态的间接影响仍是模型限制。
  不用旧请求计数改名，不承诺误差下降。请求事件及 native tag miss 保留诊断用途。
- 新采集四核、八通道，其他配置从实际 config.ini 导入 FastSim，保留 buffer TSO114。
- KVM 串行初始化并确认 main-only；O3 创建四线程，core0 达到gem5指令停止计数200万后打开 stat，实际详细 warmup 不等待完整一步/一轮。
  Graph500 的正确性验证在宿主完成，详细采集禁用验证；LBM 初始化及初始统计移到 KVM。
  固定预算未证明预热收敛；warmup 最长 600 秒，超过即停止检查，不把失败源当成完成；总 FST 不超过100GB。
- 清理旧大实验及其失败诊断 FST，保留小探针和回归输入；删除前保存路径、大小、SHA256收据，保留 JSON/报告。

## 审核重点

分片正资格与未知资格不可互相覆盖；L2/LLC 本层 miss 不等于最终供给者；
未访问下层且明确在上层命中必须是已知的非事件；合并/forwarding 不能猜测下层来源；
宏在 warmup/stat 跨界保留状态并单列缺口；缺失新字段不能降级到旧代理。

工作区采用现有托管 FastSim 工作树；本轮核实`.git`可用，分支为FastSim，保留已有混合改动，不初始化、不重置、不提交。
