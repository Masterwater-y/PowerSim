# SPR 退休 load miss：结果传递与生命周期修订方案

状态：方案修订，尚未实施本次修复或通过零 unknown 验收。
沿用 [原简化设计](2026-11-07-spr-retired-cache-simple-repair-design.md) 的事件语义、
估计规则、输入边界和两阶段框架约束。本修订明确结果写入、传递及回收要求，
依据 [小 FS 原因定位](../../spr-retired-cache-unknown-diagnosis-20261108.md)。

## 1. 用户确认的统计目标

主指标为 SPR `MEM_LOAD_RETIRED.L1_MISS/L2_MISS/L3_MISS`。
三个事件分别判断，允许同一宏同时进入多个事件，每个事件对一个宏最多计一次。

普通单片段路径：

| 实际访问结果 | L1_MISS | L2_MISS | L3_MISS |
|---|---:|---:|---:|
| L1 hit | 0 | 0 | 0 |
| L1 miss、L2 hit | 1 | 0 | 0 |
| L1/L2 miss、LLC hit | 1 | 1 | 0 |
| L1/L2/LLC miss、内存服务 | 1 | 1 | 1 |

主结果保留独立的三级位。普通路径可以用最深缺失层级辅助生成这些位，
但该辅助枚举不取代特殊服务的实际事实和估计属性。
L1/L3 按 any-read-UOP OR；L2 的多读 UOP/片段 OR 继续标为既定解释规则。

## 2. 一条主结果传递链

```text
实际 lookup / 合并 / 转发点
    → 片段的固定大小结果
    → 数据完成时转换并归并到读 UOP
    → macro 退休时三位 OR，每项最多计一次
```

- 沿用共享 `spr_retired::Result`，当前已有 `sizeof <= 16` 检查。
  查询时保留三级当前状态；完成时输出 miss/known/estimated 位。
- 每个片段只有一份当前服务结果。Request 扩展携带结果，TBE/共享服务和
  必要的活事务 ID 索引通过引用连接，不各自重新推断分类。
- 一个 UOP 的多个片段和一个宏的多个读 UOP按既有实际完成边界归并。
  宏只保存固定大小事件位、估计位及既有资格/完成信息。
- 退休读取使用共同的已完成结果适配接口。Request 扩展与 Snapshot 两种来源
  都必须传递同一 SPR Aggregate；类型专属分支只处理专属诊断字段。
- 原请求计数、旧七事件和尝试诊断保留独立用途；主事件不从它们重建服务历史。

## 3. 三项已确认缺陷的修复

### 3.1 L1 hit 必须在完成之前写入

在实际驻留 hit 的 SLICC 分支、完成回调之前写入主结果的 Resident 状态。
使用仅更新 observer 结果的操作，原 cache/profile/协议动作保持原执行顺序。
不能从最终 `externalHit` 布尔值推断此前合并点是否驻留。

覆盖普通 Load、Load_Linked、相关原子读及实际可达的完成分支。
完成回调的转换只消费已观察事实；迟到 lookup 应留下可定位诊断。

### 3.2 两种退休来源都传递主结果

将共用 SPR Aggregate 的复制移到类型专属诊断分支之外。
扩展回退、跨 warmup 边界、转发、设备服务和克隆/片段归并都走共同传递规则。
已有合法结果必须保留；纯负结果要求相关读取完整完成，
已有正 miss 证据不被缺失兄弟片段覆盖。

### 3.3 显式关闭被替换和取消的活身份

在现有请求生命周期的替换、取消、完成及 TBE 释放边上明确更新索引归属。
同 Packet 重发时旧 attempt 不得永久占用“当前活对象”索引。
仍被真实 TBE 或消费者引用的服务结果，保留到这些活引用结束。

保持固定容量保护，同时增加固定数量的生命周期诊断：
创建、正常完成、替换关闭、取消关闭、TBE retain/release、当前存量和峰值。
mode 1 在表内残留构成得到验证前，不能把单一隔离复现当作全部 FS 根因。
回收不得改变真实请求的发行、响应、store 可见性或退休；重试中仍有效的 miss
证据按既定规则保留。

## 4. 特殊路径继续用明确的 SPR 解释

- 非驻留 L1 fill follower：`{1,0,0}`，正负成员均保留估计标记。
- 非驻留 L2 follower：自己的上层事实保留，L2=1，L3 依据实际消费的共享服务。
- LLC follower：自己的上层事实保留，L3=1，标为估计。
- 完全转发/纯设备绕过：`{0,0,0}`，标为估计。
  部分转发只对实际读到的片段做分类。
- 权限、远端和软件预取沿用原设计的显式资格与解释规则。
- stale 只作为独立属性，不覆盖已经有效的 miss 位。
- 拆分、多读 UOP、重试均按实际功能成员归并，每宏每事件最多一次。

固定解释与普通公开定义的直接映射分别报告。官方未完全规定的特殊行为，
不能因实现确定输出而宣称物理 PMU 行为已经认证。

## 5. 剩余 unknown 必须逐类关闭

mode 0 的 14 个资格未知需要结合实际 opcode、功能 predicate 和成员边界判断，
不能仅凭 `U-UNSUPPORTED-ISA` 标签断言具体指令类别。
mode 2 的额外未知需要区分扩展结果丢失与合并 admission 缺观察等情况。

来源不完整时保留 unknown 并使门禁失败。资格、owner、宏边界和公共终点必须
独立检查；修复服务位传递不能替代这些检查。

## 6. 验证顺序和完成条件

1. **生产路径小测试**：复现实际 SLICC 的 action 顺序，覆盖 Request 扩展回退、
   多片段、重复完成、转发和边界；替换/取消循环证明表大小由活请求决定，
   而非随累计执行增长。
2. **三个真实小 FS 模式**：C4、32GiB、500K warmup、50K target。
   先核验模式全部采集完成、每核 load 人口非空且资格未知为零，
   三个主事件 unknown 为零；逐核正负估计守恒。
   实际服务路径单独核验，缺少的必需路径补用针对性小用例，
   不凭模式名称宣布覆盖。
3. **同一起点观察器中性**：复用受支持的 staged checkpoint，
   核对功能流、原有 native 诊断及执行计数；来源/起点不匹配则不通过。
4. **gem5/FastSim 同源回放**：相同共享规则版本，逐核 macro/UOP/load 人口、
   task 集合、输入内容和窗口一致。FastSim 仍由自身模型提供服务类型，
   使用退休功能输入和现有并行两阶段框架。
5. **四负载重采集**：前述门禁全部通过后，再运行 Marian、Graph500、XZ、FLAC
   C4、10M target、500K warmup；逐核零 unknown、独立身份和 native 守恒通过。

采集采用新目录和既定 storage guard；gem5 构建保留已知良好二进制，
使用 -j128/gold；FastSim 运行直接回归测试。
若后续评分 CPI，同时报告绝对误差和 CPI MAE，准确性与吞吐分别测量。
不做真机 perf 采集，`hardware_equivalence=unverified`。
